# 编辑指南

给你的操作手册。站点是纯静态的，改完推到 GitHub 就自动上线，不需要服务器、不需要数据库。

**线上地址：https://lheng7.github.io**

---

## 一、选一种改法

### 改法 A：在 GitHub 网页上直接改（不装任何东西）

适合改一两个错字、加一个项目。

1. 打开 <https://github.com/lheng7/lheng7.github.io>
2. 点进要改的文件 → 右上角铅笔图标 ✏️ → 改 → 底部 **Commit changes**
3. 等一两分钟，GitHub Actions 自动重新部署，刷新线上地址就能看到

**缺点**：看不见改完长什么样，得等部署完才知道；写长文容易手滑。

### 改法 B：在本地改，先预览再发布（推荐）

适合写项目复盘这种长内容。能实时看到效果，改坏了也能一眼发现。

```bash
cd ~/project_lh/mycode/personal-site
pnpm dev            # 打开 http://localhost:4321，改文件浏览器自动刷新
```

改完满意了，发布：

```bash
git add .
git commit -m "新增项目：做了个什么"
git push
```

> **这台机器上 `pnpm` 不在全局 PATH 里**（`pnpm: command not found` 就是这个原因），
> 要用 DSH 自带的那份。嫌麻烦可以给 shell 加个别名：
>
> ```bash
> # 加进 ~/.zshrc 之后，就能直接用 pnpm 了
> alias pnpm='node ~/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/pnpm/bin/pnpm.mjs'
> ```

### 改法 C：用 VS Code 打开整个文件夹

编辑体验最好，装个 Markdown 预览插件就能边写边看，再开个终端跑 `pnpm dev`。
推送用 VS Code 左侧的源代码管理面板点点鼠标也行。

## 二、加一个项目（这是主要工作）

**一个项目 = `src/content/projects/` 下的一个 `.md` 文件。** 不用改任何页面代码。

### 第 1 步：新建文件

文件名就是网址，所以**用英文或拼音**：

| 文件名 | 生成的网址 |
|---|---|
| `pid-thermostat.md` | `/projects/pid-thermostat/` |
| `campus-nav.md` | `/projects/campus-nav/` |
| `温度控制器.md` | `/projects/%E6%B8%A9%E5%BA%A6.../`（能用，但分享出去很难看） |

### 第 2 步：粘贴这个模板，改成你的内容

````markdown
---
title: PWM 调速风扇
summary: 用 STM32 的定时器输出 PWM，做无级调速，顺带测了占空比和转速的关系。
startDate: 2025-03
endDate: 2025-05
order: 0
featured: true
tags: [嵌入式, C]
links:
  - label: 源码
    href: https://github.com/lheng7/xxx
---

## 背景

为什么要做这个东西，原来有什么问题。

## 做法

用了什么方案，关键参数是什么。可以贴代码：

```c
TIM_OCInitStructure.TIM_Pulse = duty;
```

## 结果

实测数据。表格比形容词有用：

| 占空比 | 转速 (rpm) |
|---|---|
| 30% | 1200 |
| 60% | 2400 |

## 复盘

哪里做得不好，如果重做会怎么改。这一段最值钱，别省。
````

### 第 3 步：字段说明

只有 `title`、`summary`、`startDate` 三个是**必填**，其余都能省。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 项目名，卡片和详情页的大标题 |
| `summary` | ✅ | 一句话简介，显示在卡片上，别超过两行 |
| `startDate` | ✅ | `YYYY-MM` 格式，**只写年月**，写 `2025-03-15` 会报错 |
| `endDate` | | 同上；留空表示"至今" |
| `order` | | 数字，越大越靠前，默认 0 |
| `featured` | | `true` 就上首页精选区（最多 4 个），默认 `false` |
| `tags` | | `[嵌入式, C]` 这种写法，卡片上最多显示 3 个 |
| `links` | | 外部链接，`label` 是按钮文字，`href` 必须是完整网址 |
| `cover` | | 封面图，见下面「加图片」 |
| `draft` | | `true` 就不发布（本地预览也看不到），写一半可以先这样存着 |

## 三、改个人信息

**基本都在 `src/site.config.ts` 一个文件里**，改完这一处，全站跟着变。

| 想改什么 | 改哪儿 |
|---|---|
| 浏览器标签上的名字、页头标题 | `SITE.title` |
| 主页那句定位语 | `SITE.tagline` |
| 搜索结果里的描述 | `SITE.description` |
| 页脚版权署名 | `SITE.author` |
| 页脚的 GitHub / 邮箱 | `SOCIALS` 数组，不要的整行删掉 |
| 主页的标签（模拟电路、嵌入式…） | `TAGS` 数组，不要就写 `[]` |
| 顶部导航栏 | `NAV` 数组 |

邮箱同时会用在「关于」页的联系方式里，改 `SOCIALS` 里的 `mailto:` 那一行即可。

## 四、加图片

1. 把图片放到 `src/assets/`（目录不存在就建一个）
2. 在 frontmatter 里用**相对路径**引用：

```yaml
cover: ../../assets/my-photo.png
```

Astro 会自动压缩、生成多种尺寸，不用自己处理。

**正文里插图**用普通 Markdown 也行，但图片要放 `public/` 下，按绝对路径引用：

```markdown
![接线图](/images/wiring.png)
```

> 区别：`src/assets/` 的图会被优化（推荐放封面）；`public/` 的图原样复制（适合正文里随手插的截图）。

## 五、改「关于」页

- **正文段落**：直接在 `src/pages/about.astro` 里改 `<p>` 标签之间的中文
- **经历时间线**：这个文件顶部的 `timeline` 数组现在是空的，所以页面上不显示「经历」这一段。
  想加就填进去，页面会自动渲染：

```js
const timeline = [
  { when: '2025 年 3 月 – 6 月', what: '做了什么', detail: '一句话说明。' },
];
```

## 六、发布和反悔

### 发布

```bash
git add .
git commit -m "说清楚这次改了什么"
git push
```

推送后自动构建部署，一两分钟生效。进度看
[Actions](https://github.com/lheng7/lheng7.github.io/actions)，绿勾就是成功了。

### 改错了想撤回

- **还没 push**：`git checkout -- 文件名` 丢弃改动
- **已经 push 了**：`git revert HEAD` 再 push 一次，或者在 GitHub 网页上找到那次提交点 **Revert**
- **只是想先别上线**：在 frontmatter 里把 `draft` 改成 `true`

## 七、常见问题

**构建失败，报 `startDate` 格式错误**
日期必须是 `YYYY-MM`，`2025-3` 和 `2025-03-15` 都不行，要补零。

**首页没有我的项目**
检查 `featured: true`，或者看看 `draft` 是不是 `true`。

**改完线上没变化**
① 是不是忘了 `git push`；② Actions 还在跑，等一分钟；③ 浏览器缓存，`Cmd+Shift+R` 强制刷新。

**想换配色 / 字体**
`src/styles/global.css` 开头的 `:root` 里那几个变量，改 `--accent` 就换主色，改 `--bg` 换背景。

**想改页脚那句「没有用任何追踪脚本」**
在 `src/pages/about.astro` 底部，直接改文字。

**不小心把站点搞坏了**
代码都在 GitHub 上，最坏情况重新 clone 一次：

```bash
cd ~/project_lh/mycode
mv personal-site personal-site-broken
git clone git@github.com:lheng7/lheng7.github.io.git personal-site
cd personal-site && pnpm install
```
